# 역할과 모델 배분

역할은 조사 책임을 정의하며 모델명이나 추론 옵션을 지정하지 않는다. 실제 모델은 선택한 프로파일의 역할별 별칭과 현재 클라이언트의 연결 설정에서 결정한다. 기본 프로파일은 모델을 덮어쓰지 않고 클라이언트의 상속·기본값을 따른다. 설정 형식과 생성 절차는 [configuration.md](configuration.md)를 따른다.

| 역할 | 과업과 상향 조건 |
| --- | --- |
| 주 조사자 | 대상·가설·우선순위·전체 근거 연결, 중요한 결론 직접 확인, 정본 기록 병합 |
| `inventory` | 범위가 명확한 파일·등록·심볼·설정 목록과 줄 근거 수집. 동적 등록·복잡한 권한·상태·상충 증거는 분석 역할로 전달 |
| `analyst` | 아키텍처·업무 속성·경로·권한·비동기 상태·가설 분석, 도구 질의 해석 |
| `reviewer` | 중요한 가설의 독립 반증, 영향 확대·부당한 기각·누락된 통제와 검토 공백 확인 |

하위 역할 지침의 정본은 [inventory](../roles/inventory.md), [analyst](../roles/analyst.md), [reviewer](../roles/reviewer.md)다. 네이티브 이름은 각각 `static_inventory`, `static_analyst`, `static_reviewer`를 사용한다. 역할 간 난도·비용·검토 독립성을 고려해 사용자가 모델을 연결하며, 모델 이름 자체를 능력이나 탐지 정확도의 보증으로 취급하지 않는다.

## 실제 적용

하나의 가벼운 검색을 위해 여러 에이전트를 호출하지 않는다. 독립 범위가 있을 때 위임하고 프로파일의 동시 작업 수를 호스트가 허용하는 한도 안에서 적용한다. 현재 사용자의 위임·비용·모델 제한이 우선한다. 실패를 같은 인수로 반복하지 말고 범위·근거·설정을 조정한다.

네이티브 설정의 발견, 하위 에이전트 호출, 역할별 모델 선택, 추론 옵션, 도구·MCP 상속은 클라이언트마다 다르다. 선택한 어댑터 정보와 현재 세션이 노출한 기능을 확인한다. 문서나 생성 파일만으로 실제 적용을 단정하지 않는다. 모델 변경이 별도 컨텍스트를 요구하면 작업에 필요한 원시 경로·버전·질문만 전달하며 부모 전체 이력을 복제할 수 있다고 가정하지 않는다.

모델 카탈로그나 로컬 실행 파일의 존재는 계정 접근·현재 세션 모델·위임 가능성의 증거가 아니다. 지정 모델·옵션이 지원되지 않거나 접근 여부가 불명확하면 이를 기록한다. 명시적으로 선택한 모델을 다른 모델로 바꾸려면 사용자 설정이나 현재 지시의 근거가 있어야 한다. 클라이언트가 자체 대체 동작을 수행하면 관찰한 변경을 기록한다.

네이티브 위임을 사용할 수 없으면 현재 세션에서 가능한 조사와 반증을 진행하고 독립 검토가 미수행임을 남긴다. 충분한 능력·근거가 없는 결론은 미검토 또는 추가 근거 필요 상태를 유지한다. 준비가 필요해도 자격증명을 파일에서 추출하거나 별도 API 호출 경로를 만들지 않는다.

## 작업 기록

`notes/model-usage.jsonl` 등에 `task_id`, `role`, `client`, `profile`, `requested_model`, `actual_model`, `requested_options`, `actual_options`, `scope`, `result_path`, `limitations`, `reviewed_by`를 남긴다. 실제 모델이나 적용 옵션이 제공되지 않으면 값을 `null`로 두고 이유를 적는다. 모델 ID와 별칭, 요청 옵션과 실제 확인한 옵션을 구분하며 비밀값은 기록하지 않는다. 호출하지 않은 역할을 완료로 표시하지 않는다.

자식은 지정된 노트만 쓰고 정본 finding·coverage 병합은 주 조사자가 한다. 중요한 결론은 요약만으로 확정하지 않고 원시 소스와 대조한다. 독립 반증자에게 결론을 정답으로 주지 않으며 대안 해석과 통제의 적용 범위를 검토하게 한다. 같은 세션의 재검토를 별도 검토자의 독립 검토로 기록하지 않는다.
