# 모델 역할 배분

이 배분은 비용과 조사 난도를 맞추기 위한 기본값이다. 특정 모델의 탐지율이나 보안 정확도를 보증하지 않는다. 현재 계정·클라이언트의 사용 가능한 정확한 모델과 reasoning을 우선한다. 기본 설정 파일은 IDE에서도 확인 가능한 예시 ID `gpt-6-luna`, `gpt-6.1-sol`을 사용한다. 제품의 현재 기본 모델이라는 뜻은 아니다.

| 역할 | 기본 모델·노력 | 과업과 상향 조건 |
| --- | --- | --- |
| 주 조사자 | 사용 가능한 Sol, high 이상이 유효한 경우 | 대상·가설·우선순위·전체 근거 연결, 중요한 결론 직접 검토 |
| `static_inventory` | Luna, high | 명확한 범위의 파일·등록·심볼·설정 목록과 줄 근거 수집. 동적 등록·복잡한 권한/상태·상충 증거는 Sol로 상향 |
| `static_analyst` | Sol, high | 아키텍처, 업무 속성, 경로·권한·비동기 상태 분석, 도구 질의 해석 |
| `static_reviewer` | Sol, xhigh가 지원되는 경우 | 중요한 가설의 독립 반증, 영향 확대와 부당한 기각·미검토 확인 |

하나의 가벼운 검색을 위해 여러 모델을 호출하지 않는다. 독립적으로 조사할 범위가 있을 때 위임하고 현재 실행 슬롯을 따른다. kit의 기본 동시 하위 스레드 상한은 3이지만 호스트 제한을 넘기지 않는다. 한 하위 에이전트의 실패를 같은 인수로 반복하지 말고 모델·증거·범위를 조정한다.

## 실제 적용

`.codex/agents/*.toml`은 네이티브 custom agent를 지원하는 클라이언트의 설정이다. 현재 세션에서 자동 발견되지 않으면 해당 파일의 역할 지침과 명시적 모델 ID·reasoning을 지원되는 spawn 기능에 전달한다. 모델을 명시적으로 바꿀 때는 새 최소 컨텍스트로 위임하고 필요한 원시 경로와 버전을 준다. 다른 모델에 부모 전체 이력을 복제할 수 있다고 가정하지 않는다.

`scripts/capabilities.py`의 모델 캐시는 카탈로그 힌트이며 실시간 계정 접근이나 reasoning 지원을 보증하지 않는다. 호스트의 모델 목록·에이전트 기능과 실제 호출 결과로 확인한다. Luna 또는 Sol이 가용하지 않으면 가능 모델로 조정하고 실제 ID·노력·이유를 기록한다. 핵심 검토에 충분한 모델이 없으면 결론의 미검토 상태를 유지한다.

대표 프롬프트를 읽는 것만으로 부모 세션 모델이 전환되지는 않는다. 부모 모델의 기능이 충분하면 배분과 조사를 진행한다. 모델 변경이 필요하지만 호스트에서 불가능하면 재개 프롬프트와 checkpoint를 남기며 가능한 업무를 수행한다. 계정 자격증명을 파일에서 추출하거나 별도 API 키 호출 경로를 만들 필요는 없다.

`notes/model-usage.jsonl` 등에 과업별 `task_id`, `role`, `requested_model`, `actual_model`, `reasoning_effort`, `scope`, `result_path`, `limitations`, `reviewed_by`를 남긴다. 실제 ID가 제공되지 않으면 `actual_model: null`과 이유를 적는다. 호출되지 않은 역할을 호출 완료로 기록하지 않는다.

자식은 전용 노트만 쓰고 정본 finding·coverage 병합은 주 조사자가 한다. 중요한 결론은 요약만 신뢰하지 않고 원본 코드에서 재확인한다. 독립 반증자는 현재 주장의 결론을 정답으로 받지 않으며, 동일 자료에 대한 대안 해석과 통제의 실제 적용을 검토한다.
