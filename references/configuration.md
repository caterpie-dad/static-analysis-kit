# 클라이언트 설정과 모델 프로파일

공통 조사 지침과 역할은 저장소의 정본 파일에서 관리한다. 모델 연결은 프로파일, 네이티브 설정 형식은 어댑터가 담당한다. 기본 프로파일은 모델을 덮어쓰지 않고 클라이언트의 상속·기본값을 따른다. 특정 클라이언트·모델·공급자에 대한 접근 권한을 키트가 부여하지 않는다.

## 파일과 적용 순서

| 위치 | 책임 |
| --- | --- |
| [kit.toml](../kit.toml) | 키트 요구사항과 공통 구성 |
| [roles/](../roles/) | 모델명이 없는 역할 지침 |
| [profiles/default.toml](../profiles/default.toml) | 클라이언트의 상속·기본값을 따르는 기본 역할 배정 |
| [profiles/models.example.toml](../profiles/models.example.toml) | 명시적으로 모델을 지정하는 선택적 예시 |
| [adapters/](../adapters/) | 클라이언트별 네이티브 경로·생성 방식·지원 옵션과 문서 기준 |
| 사용자가 지정한 로컬 TOML | 개인 역할 배정과 모델·옵션 변경 |
| 생성된 네이티브 파일 | 해당 클라이언트가 읽는 설정. 공통 지침의 정본이 아님 |

기본값, 선택한 `--profile`, 명시한 `--override`를 순서대로 적용한다. 로컬 설정은 자동으로 탐색하거나 불러오지 않는다. 사용할 파일을 직접 지정하고 Git에서 제외한다. 프로파일을 수정한 뒤 네이티브 파일을 다시 생성하며, 생성 파일을 수작업으로 고쳐 공통 정본과 별개로 유지하지 않는다.

프로파일은 키트용 TOML이다. 각 제품의 네이티브 설정 파일로 직접 사용하지 않는다.

```toml
schema_version = 1

[roles]
inventory = "inherit"
analyst = "inherit"
reviewer = "inherit"

[delegation]
max_concurrent = 3
```

`inherit`는 키트에서 모델을 덮어쓰지 않는 예약 별칭이다. 어댑터가 모델 필드 생략 또는 해당 클라이언트의 상속 구문으로 변환한다. 클라이언트의 하위 에이전트 기본값이 있으면 부모와 다른 모델이 선택될 수 있으므로 실제 적용 모델을 따로 확인한다. 동시 작업 수는 운영상 요청 한도이며, 클라이언트에 해당 설정이 없으면 호스트가 이를 강제한다고 주장하지 않는다.

역할별 모델을 선택할 때는 `[roles]`에 사용자 별칭을 넣고 `[clients.CLIENT.models]`에 그 별칭과 해당 클라이언트에 등록된 모델 참조를 연결한다. 별칭과 모델 ID는 임의 문자열이며 특정 공급자의 이름 목록으로 제한하지 않는다. 클라이언트별 모델 참조 형식·공급자 설정·접속 가능 여부는 별도로 확인한다. 서버 주소·공급자·인증 연결은 해당 클라이언트의 기존 설정에 둔다.

추론 등 선택 옵션은 `[clients.CLIENT.options.ALIAS]`에 네이티브 키로 지정한다. 어댑터는 지원하는 키와 타입을 검사하며 다른 모델이나 클라이언트의 옵션으로 임의 번역하지 않는다. 모델 자체의 옵션 지원과 실제 계정 접근은 오프라인 검사로 확인되지 않는다. 필요한 옵션을 표현하지 못하는 어댑터는 프로파일을 조용히 축소하지 말고 오류나 제약을 드러내야 한다.

별칭별 옵션 테이블은 다음 설정 계층에서 전체 교체한다. 모델을 바꾸면서 기존 옵션을 제거하려면 로컬 override에 빈 `[clients.CLIENT.options.ALIAS]` 테이블을 명시한다. 옵션 일부를 유지하려면 유지할 값도 그 테이블에 함께 적는다.

## 계획·생성·갱신

키트 루트에서 다음 명령으로 생성 계획을 검토한다. `CLIENT`는 `codex`, `claude-code`, `mistral-vibe`, `opencode` 중 선택한다.

```bash
python3 scripts/configure.py --client CLIENT
python3 scripts/configure.py --client CLIENT --profile profiles/default.toml --override models.local.toml
python3 scripts/check_kit.py --client CLIENT --profile profiles/default.toml --override models.local.toml
```

기본 출력은 파일 내용·해시와 해석한 역할 배정을 담은 JSON 계획이다. 파일 쓰기, CLI 실행, 로그인, 모델 호출, 패키지 설치는 수행하지 않는다. 기존 파일과 충돌하면 계획에도 충돌을 표시하고 종료 코드가 실패가 된다. `--write`로 생성을 선택한다.

```bash
python3 scripts/configure.py --client CLIENT --override models.local.toml --write
python3 scripts/configure.py --client CLIENT --output /path/to/staging --write
```

기본 출력 루트는 `KIT_ROOT`다. 생성기는 지정한 출력 루트의 네이티브 파일과 `.tools/adapter-state/CLIENT.json`에 생성 소유권·해시를 기록한다. 기존 사용자 파일을 덮어쓰거나 기존 설정을 추측해 병합하지 않는다. `--force`는 이전 생성 기록과 현재 파일의 해시가 일치하는 생성물의 갱신에만 사용한다. 수작업 수정이나 소유권을 확인할 수 없는 충돌은 별도로 정리한다.

기존 파일이 생성할 내용과 같으면 그대로 사용하지만 생성기 소유로 편입하지 않는다. 이후 내용이 달라지는 갱신에서는 사용자 파일로 보호한다.

생성된 프롬프트·진입 파일에는 실제 `KIT_ROOT`의 절대 경로가 들어간다. `--output` 결과는 네이티브 설정을 검토·배치하기 위한 산출물이며 독립된 키트 복제본이 아니다. 키트 checkout을 이동하면 설정을 다시 생성한다. 대상 소스 루트에는 설정을 자동 설치하지 않는다.

## 클라이언트별 경계

| 클라이언트 | 생성·발견 방식과 제한 |
| --- | --- |
| Codex | `.codex/config.toml`과 `.codex/agents/*.toml`을 생성한다. 공통 스킬은 `.agents/skills/`에서 발견한다. 모델·추론 선택은 현재 클라이언트와 부모 세션의 공급자·권한 제한을 따른다. |
| Claude Code | `.claude/agents/*.md`와 스킬 진입 파일, 공통 운영 지침을 가져오는 `CLAUDE.md`를 생성한다. 기존 `CLAUDE.md`가 있으면 덮어쓰지 않는다. 설정·스킬 발견은 클라이언트 버전과 시작 디렉터리의 영향을 받는다. |
| Mistral Vibe | `.vibe/agents/*.toml`에 역할 지시와 선택한 `active_model`을 전달한다. 모델의 thinking 설정은 기존 네이티브 모델 프리셋에서 관리한다. 하위 에이전트의 도구 범위가 주 세션과 같다고 가정하지 않는다. |
| OpenCode | `.opencode/agents/*.md`를 V1 호환 형식으로 생성한다. 기존 프로젝트 JSON/JSONC, 공급자·MCP·플러그인 설정을 변경하지 않는다. 현재 웹 문서의 V2 전용 설정을 설치된 V1에 적용하지 않는다. |

공통 `.agents/skills/`를 발견하는 클라이언트에는 스킬을 중복 등록하지 않는다. 자동 발견을 지원하지 않거나 제한된 환경에서는 `START_HERE.md`를 명시적으로 읽어 공통 조사를 진행한다. 네이티브 파일 생성·형식 검사와 실제 클라이언트에서의 로딩·모델 적용 확인은 별개의 검증이다. 지원 버전과 검증 수준은 어댑터 정보 및 [VALIDATION.md](../VALIDATION.md)를 확인한다.

모든 클라이언트의 디렉터리 추가 옵션이 같은 의미는 아니다. Vibe의 `--add-dir`은 해당 경로를 세션에서 신뢰하고 그 안의 지침·설정을 읽으며 편집 접근도 허용한다. 대상 원본 비수정과 대상 지침을 분석 정책으로 실행하지 않는 요구는 각 호스트의 파일 접근·격리·설정 로딩 방식에 맞게 유지한다. 프롬프트나 스킬의 도구 목록만으로 이를 강제할 수 있다고 가정하지 않는다.

## 의존성과 실행 기록

에이전트 CLI는 공식 배포 방법으로 준비하며 키트는 네이티브 설정과 요구사항만 관리한다. 공통 헬퍼를 위해 여러 에이전트 SDK나 모든 분석기를 설치하지 않는다. 선택한 Python 분석기는 기존 독립 설치 헬퍼를 사용할 수 있고, 네이티브 도구·플러그인·MCP 서버는 해당 생태계의 설치·잠금 파일과 공식 출처를 사용한다.

의존성 기록에는 이름·공급처·버전 또는 commit/digest·아티팩트 해시·선택 이유·플랫폼·실제 명령을 남긴다. 설치 후 남긴 해시 기록을 사전 고정한 잠금 파일이나 서명 검증과 동일하게 취급하지 않는다. 외부 스킬은 필요한 파일과 권한을 읽고 버전·출처를 고정한다. 모델은 로컬 패키지처럼 설치되는 의존성으로 취급하지 않으며, 변경될 수 있는 별칭과 실제 확인된 모델 ID를 구분한다.

개인 모델 연결과 경로는 로컬 override에, 비밀값은 기존 클라이언트 인증 저장소나 환경변수에 둔다. 키트 프로파일·생성 계획·로그에는 자격증명을 넣지 않는다. 클라이언트 설정 전체를 모델 카탈로그로 읽거나 출력하지 않는다.

조사별로 선택한 프로파일과 해시, 클라이언트·CLI 버전, 요청 모델·옵션과 실제 관찰한 값, 위임·도구 제약 및 대체 동작을 기록한다. 캐시된 모델 목록, 실행 파일의 존재, 요청한 모델, 실제 적용 모델은 서로 다른 사실이다. 값이 확인되지 않으면 미확인으로 남긴다. 구체 기록은 [model-routing.md](model-routing.md)를 따른다.

## 선택적 보안 플러그인

Codex Security는 Codex 환경에서 사용할 수 있는 선택적 연동이다. 현재 클라이언트가 제공하는 공식 플러그인 설치 기능과 도움말을 확인하고 계정·관리자 제약을 따른다. 공통 키트 사용이나 다른 클라이언트의 분석을 위한 필수 의존성이 아니다.

지원되는 전체 소스 스캔 기능을 사용할 때에는 먼저 해당 스킬과 공식 문서를 읽고 정적 분석 범위, 대상 원본 비수정, 실행·재현·자동 수정 제외를 전달한다. 산출물은 조사 폴더의 `tools/` 아래에 보존하고 같은 증거 기준으로 검토한다. 현재 환경에서 이 범위를 지킬 수 없으면 다른 정적 수단을 선택한다.
